Trang 2 / 3 · Viết command

Thêm, bỏ, thay command (API) và đường đi của một request

Handler không đọc hay ghi database — framework làm hộ. Xem ngay bảng đối chiếu từng bước với code.

Đúng với commit 175df65 (nhánh 012-analytics-audit, tài liệu làm trên docs-html-guides).

1. Điều quan trọng nhất: handler không đọc hay ghi database #

Mô hình quen thuộc khi viết API: nhận message → phân loại → xử lý logic → đọc param → get DB → update → save DB → trả response. Trong framework này, các bước đó vẫn có đủ, nhưng ba bước liên quan tới database do framework làm, không phải code của command:

  • Trước khi gọi handler, CommandRunner mở một transaction và đọc sẵn mọi aggregate khai trong Touches và Reads của command (cộng receipt để chống chạy trùng).
  • Handler chỉ làm việc với ICommandContext: ctx.Get<T>(id) lấy bản sao đã đọc, ctx.Set(id, newState) ghi vào bộ đệm.
  • Sau khi handler trả Ok, CommandRunner ghi các aggregate đã đổi với rev + 1, ghi receipt, và commit tất cả trong cùng một transaction. Nếu handler trả Reject, transaction rollback — không có gì được ghi.
  • Client gửi lại cùng X-Request-Id → framework trả lại kết quả cũ từ receipt (replay), handler không chạy lần hai.

Vì vậy handler phải "thuần": không gọi HTTP, không gọi DB, không đọc giờ hệ thống; transaction có thể chạy lại handler nhiều lần khi có xung đột (comment của ICommandHandler trong src/GameServer.Core/Commands/ICommandHandler.cs).

2. Sơ đồ sequence một command (Sơ đồ C) #

Lifeline (trái → phải):

  1. Unity: GameServerClient
  2. ASP.NET pipeline (gom các middleware)
  3. Endpoint (CommandEndpointFactory)
  4. CommandRunner
  5. Handler (IncrementHandler)
  6. Couchbase (transaction)
  7. OutboxRelay

Thông điệp (đánh số đúng như mục 3):

3. Đường đi chi tiết khi nhận một command #

Tham chiếu: src/GameServer.Platform.Web/Hosting/GameServerApplicationExtensions.cs (thứ tự middleware ≈ dòng 64–80), src/GameServer.Platform.Web/Commands/CommandEndpointFactory.cs, src/GameServer.Platform/Commands/CommandRunner.cs.

Bước 1 — Unity gửi request #

GameServerClient.SendCommandAsync(route, request, resultParser) (sdk/unity/com.gameserver.client/Runtime/Core/GameServerClient.cs): serialize body một lần, gửi POST Protobuf với header X-Request-Id (UUID mới), X-Client-Version, X-Platform, X-Build-Id, Authorization: Bearer <token>. Khi retry (lỗi mạng, COMMIT_UNKNOWN_RETRY, CONCURRENT_UPDATE, RATE_LIMITED…) gửi lại đúng bytes và đúng X-Request-Id.

Bước 2 — Kestrel và ForwardedHeaders #

Kestrel nhận request. Nếu cấu hình reverse proxy (GameServer:Hosting:ForwardedHeaders), UseForwardedHeaders chạy đầu tiên để IP client lấy từ proxy tin cậy.

Bước 3 — ExceptionMiddleware (ngoài cùng) #

src/GameServer.Platform.Web/Middleware/ExceptionMiddleware.cs. Bọc toàn bộ phần sau. Đổi exception thành response lỗi: GameServerException → mã trong catalog; body Protobuf hỏng → 400 BAD_REQUEST; body quá lớn → PAYLOAD_TOO_LARGE; exception lạ → 500 INTERNAL (không lộ chi tiết). Route không tồn tại → 404 NOT_FOUND. Ghi bằng ErrorResponseWriter (Protobuf ErrorEnvelope cho Player API, JSON cho GM).

Bước 4 — CorrelationMiddleware #

src/GameServer.Platform.Web/Middleware/CorrelationMiddleware.cs. Đọc X-Request-Id: UUID hợp lệ → dùng làm correlation id và requestId của command; không hợp lệ → server tự sinh id chỉ để log (command sẽ bị từ chối ở bước 8). Trả lại header X-Request-Id, gắn vào log scope và trace.

Bước 5 — Routing (phân loại lần 1) #

app.UseRouting() chọn endpoint theo method + route. Endpoint của command được tạo lúc khởi động bởi MapPlayerCommand (bước 8), mang theo tên operation (vd. "counter.increment") và metadata profile Player, gate, timeout, rate limiter.

Bước 6 — GateMiddleware (trước xác thực) #

src/GameServer.Platform.Web/Middleware/GateMiddleware.cs. Chỉ áp cho endpoint có GateMetadata (Player API và login). StoreGateEvaluator đọc document gate (cache ≤ GameServer:Gate:CacheSeconds, mặc định 10 s): đang bảo trì → 503 MAINTENANCE; X-Client-Version thấp hơn tối thiểu của X-Platform → 426 UPDATE_REQUIRED.

Bước 7 — ProfileEnforcementMiddleware (xác thực + phân quyền) #

src/GameServer.Platform.Web/Middleware/ProfileEnforcementMiddleware.cs. Pipeline không dùng UseAuthentication; middleware này xác thực theo profile của endpoint:

  • Endpoint không có profile → 403 (deny-by-default).
  • Đặt giới hạn body theo profile (GameServer:Limits:PlayerBodyBytes = 64 KiB).
  • Profile Player → gọi scheme PlayerBearer = PlayerBearerAuthenticationHandler (src/GameServer.Modules.Identity.Adapters/PlayerBearerAuthenticationHandler.cs): token → session → profile; kiểm theo thứ tự tài khoản đã xoá (ACCOUNT_DELETED) → bị khoá login (ACCOUNT_SUSPENDED) → phiên cũ (session.Epoch < profile.SessionEpoch → SESSION_REPLACED). Thất bại → UNAUTHENTICATED hoặc mã tương ứng.
  • Profile Gm → cookie GM, CSRF cho thao tác ghi, permission của endpoint.

Sau đó UseRequestTimeouts (Player 10 s) và UseRateLimiter (concurrency command toàn instance, mặc định 200 + hàng đợi; quá thì RATE_LIMITED).

Bước 8 — Endpoint của MapPlayerCommand (đọc param) #

CommandEndpointFactory.MapCommand (≈ dòng 88–130):

  1. ProtobufBinding.ReadBodyAsync(http, options.Limits.PlayerBodyBytes) — đọc raw body.
  2. CorrelationMiddleware.GetClientRequestId(http) — thiếu hoặc không phải UUID → 400 BAD_REQUEST.
  3. ProtobufBinding.Parse<TWireRequest>(body) — message wire (vd. Sample.Counter.Protocol.V1.IncrementRequest).
  4. ActorContextAccessor.GetActor(http) — actor (playerId) từ bước 7.
  5. ReceiptIds.BodyHash(body) — SHA-256 của raw body (để phát hiện cùng requestId mà khác body).
  6. toDomain(wire) — hàm của module: validate và đổi wire → record domain (vd. IncrementCommand). Lỗi → ném GameServerException(CoreErrorCodes.BadRequest, ...) → 400.
  7. Tạo CommandInvocation(operation, actor, requestId, bodyHash, request, encodeResult) rồi gọi ICommandRunner.ExecuteAsync.

Biến thể toDomainAsync (IAP, identity.link): gọi runner.TryReplayAsync trước để retry không gọi lại store/provider.

Bước 9 — CommandRunner (phân loại lần 2, get DB, logic, save DB) #

src/GameServer.Platform/Commands/CommandRunner.cs:

9.1 ExecuteCoreAsync (≈ dòng 55–113)

  • registry.GetCommand(invocation.Operation) → CommandRegistration (descriptor + kiểu handler). Operation không đăng ký → 404 NOT_FOUND.
  • EnsureActorAllowed: command Player chỉ cho actor Player, command GM cần permission.
  • limiter.AcquireAsync(playerId) (PerPlayerCommandLimiter): mỗi player chạy một command một lúc trên instance, hàng đợi GameServer:Commands:PerPlayerQueueLimit (2); đầy → 429 RATE_LIMITED.
  • ReceiptIds.Compute(actorId, playerId, operation, requestId) → receiptId, key receipts/rcpt::{receiptId}.
  • Đường replay nhanh (ngoài transaction): store.GetAsync(receiptKey); có receipt trong replay window (24 h, GameServer:Commands:ReplayWindowHours) → ReplayAsync: body hash khác → 409 IDEMPOTENCY_PAYLOAD_MISMATCH; giống → trả code, receiptId, result y hệt lần đầu, replayed = true, kèm state hiện hành của các aggregate client-visible.
  • Các ICommandGuard (vd. BanCommandGuard, src/GameServer.Modules.Identity.Adapters/BanCommandGuard.cs) — chỉ chặn lần chạy mới; bị chặn → ACCOUNT_SUSPENDED.
  • Gọi ExecuteTransactionAsync; đua insert receipt/claim (DocumentExistsException) hoặc StaleReadException → chạy lại tối đa 3 vòng (vòng sau thường gặp receipt và replay); hết → 409 CONCURRENT_UPDATE.

9.2 ExecuteTransactionAsync (≈ dòng 161–239)

  • Dựng keys = aggregate trong Touches ∪ Reads (key pa_{aggregateId}/{playerId}) + receipt key.
  • store.RunTransactionAsync(tx => RunAttemptAsync(...), ExpirationSeconds = 10). Từ đây không dùng token huỷ của request: client ngắt kết nối không làm hỏng commit.
  • Lỗi transaction: commit không rõ → 503 COMMIT_UNKNOWN_RETRY; hết hạn → 409 CONCURRENT_UPDATE; thất bại → 500 INTERNAL.

9.3 RunAttemptAsync (≈ dòng 241–347) — một lần thử trong transaction:

  1. Get DB: tx.GetManyAsync(keys). Nếu receipt đã có (instance khác vừa commit) → replay.
  2. serializer.Load(descriptor, playerId, document) cho từng aggregate: không có document → state mặc định (createDefault), rev = 0; schemaVersion cũ → chạy upgrader; mới hơn code → 500.
  3. Tạo CommandContext (actor, now = IClock.UtcNow cố định cho lần thử, config, aggregate đã đọc).
  4. ActivatorUtilities.CreateInstance(services, registration.HandlerType) rồi registration.InvokeAsync(handler, request, ctx) → handler chạy logic.
  5. Outcome không OK → ném nội bộ → rollback, không receipt. Mã HTTP 200 (mã nghiệp vụ) → CommandResponse với code; mã khác 200 → ErrorEnvelope.
  6. invocation.EncodeResult(result) → bytes kết quả (hàm toWire của module chạy ở đây, trong transaction); > 512 B (GameServer:Commands:ResultCompactMaxBytes) → lỗi lập trình (500).
  7. Save DB: với mỗi aggregate trong Touches mà handler đã Set và state thực sự đổi: newRev = rev + 1, serializer.BuildDocument (> 64 KiB → AGGREGATE_TOO_LARGE), rồi tx.InsertAsync (document mới) hoặc tx.ReplaceAsync. Aggregate không đổi giữ nguyên rev.
  8. Insert claim marker (ctx.TryClaimAsync).
  9. EnsureAudit: command GM phải có đúng 1 audit, command khác 0.
  10. BuildReceipt (requestId, bodyHash, resultCode, resultCompact, các aggregate đã ghi và rev mới, outbox, commit time) — > 4 KiB → 500; insert receipt. Kết thúc lambda → store commit.

9.4 Sau commit (≈ dòng 212–238)

  • relay.TryRelayAsync(...) nếu receipt có outbox (GameServer:Outbox:InlineRelayEnabled); thất bại thì OutboxSweeper giao lại.
  • Dựng AggregateChange cho các aggregate client-visible đã ghi → CommandExecution.

Bước 10 — Response #

CommandEndpointFactory.BuildResponse (≈ dòng 132–157): CommandResponse (proto/gameserver/core/v1/core.proto) gồm code, code_number, receipt_id (rỗng khi bị từ chối), result (bytes kết quả của module), config_version, server_time_utc_ms, replayed, updates (mỗi aggregate đổi: id, base_rev, new_rev, payload qua wire mapper đăng ký bằng AddAggregateWireMapper, full = true). Ghi bằng ProtobufBinding.WriteAsync, HTTP 200.

Lỗi ở bất cứ bước nào → ExceptionMiddleware ghi ErrorEnvelope (code, code_number, message, request_id, retryable, retry_after_ms, server_time_utc_ms, config_version, details).

Bước 11 — Unity nhận kết quả #

SendCommandAsync áp updates vào client.Sections theo rev; nếu lệch thì tự gọi snapshot cho section đó; parse result khi code == "OK". Sau khi server đã trả lời, phương thức không ném lỗi (báo qua SectionsStale, ResultUnreadable) để game không vô tình gửi lại bằng requestId mới.

4.2 Aggregate, record command/result, error code — project nghiệp vụ #

modules/Sample.Counter/Sample.Counter/CounterModel.cs (trích):

C#
public sealed record CounterState
{
    public long Value { get; init; }

    public int Increments { get; init; }
}

public sealed record IncrementCommand(long By, string? Note);

public sealed record IncrementResult(long Value);

public static class CounterAggregates
{
    public const string Counter = "counter";

    public static PlayerAggregateDescriptor<CounterState> CounterDescriptor { get; } =
        new(Counter, schemaVersion: 2, clientVisible: true, createDefault: () => new CounterState(), upgraders: [V1ToV2]);
}

public static class CounterErrors
{
    public static readonly ErrorCode LimitExceeded = new(10001, "COUNTER_LIMIT_EXCEEDED", 200, false, "The increment exceeds the allowed amount.");
    public static readonly ErrorCode InvalidAmount = new(10002, "COUNTER_INVALID_AMOUNT", 200, false, "The increment must be positive.");

    public static ErrorCodeSet All { get; } = new(10000, 10099, LimitExceeded, InvalidAmount);
}
  • Record command/result là type domain, không phải message Protobuf (test kiến trúc Command_handlers_receive_domain_types_not_wire_messages chặn).
  • ErrorCode(number, name, httpStatus, retryable, message): mã nghiệp vụ dùng HTTP 200. Mỗi module một dải số riêng, không chồng dải đã dùng (core 0–999, Counter 10000–10099, Economy 11000–11099, IAP 12000–12099, GM 13000–13099, Identity 14000–14099, SampleGame 40000–40099, template 90000–90099). Tên viết UPPER_SNAKE_CASE.

4.3 CommandDescriptor và handler — logic #

modules/Sample.Counter/Sample.Counter/IncrementHandler.cs (trích):

C#
public sealed class IncrementHandler(ICounterLimitPolicy policy) : ICommandHandler<IncrementCommand, IncrementResult>
{
    public const string Operation = "counter.increment";
    public const string LogKind = "counter_log";

    public static CommandDescriptor Descriptor { get; } = new(Operation, touches: [CounterAggregates.Counter]);

    public ValueTask<CommandOutcome<IncrementResult>> HandleAsync(IncrementCommand request, ICommandContext context)
    {
        if (request.By <= 0)
        {
            return ValueTask.FromResult(CommandOutcome<IncrementResult>.Reject(CounterErrors.InvalidAmount));
        }

        if (request.By > policy.MaxPerIncrement)
        {
            return ValueTask.FromResult(CommandOutcome<IncrementResult>.Reject(CounterErrors.LimitExceeded));
        }

        var state = context.Get<CounterState>(CounterAggregates.Counter);
        var next = state with { Value = checked(state.Value + request.By), Increments = state.Increments + 1 };
        context.Set(CounterAggregates.Counter, next);
        context.AddOutbox(LogKind, new CounterLogEntry(request.By, request.Note, next.Value));
        return ValueTask.FromResult(CommandOutcome<IncrementResult>.Ok(new IncrementResult(next.Value)));
    }
}

Đọc đoạn này theo mô hình của bạn:

  • Descriptor: touches: [counter] = "command này đọc và có thể ghi aggregate counter". Muốn chỉ đọc thêm aggregate khác thì thêm reads: [...]. Framework dựa vào đây để get DB trước khi gọi handler.
  • context.Get<CounterState>(...) = dữ liệu đã được framework đọc sẵn (bản sao, sửa thoải mái).
  • context.Set(...) = "save" vào bộ đệm; framework ghi thật sau khi handler trả Ok.
  • context.AddOutbox(...) = hiệu ứng phụ commit cùng transaction.
  • Reject(...) = không ghi gì.
  • Policy ICounterLimitPolicy được tiêm qua constructor (thay được, mục 7).

Các khả năng khác của ICommandContext (src/GameServer.Core/Commands/ICommandHandler.cs): Actor, Now (giờ server cố định cho lần thử), Config/ConfigVersion (game config), TryClaimAsync(collection, key) (hiệu ứng "chỉ một lần", cần khai maxClaimMarkers trong descriptor), NewId(purpose) / NewSeed(purpose) (id và seed ngẫu nhiên ổn định qua các lần retry). Extension: ctx.AddAudit(...) (GM, src/GameServer.Core/Commands/Audit.cs), ctx.AddAnalyticsEvent(...) (src/GameServer.Core/Analytics/AnalyticsEvents.cs).

4.5 Adapter: đăng ký DI, wire mapper, MapPlayerCommand, ToDomain #

modules/Sample.Counter/Sample.Counter.Adapters/CounterModule.cs (trích):

C#
public sealed class CounterModule : IGameModule, IPlayerApiModule, IGmApiModule
{
    public const int MaxNoteLength = 64;

    public ModuleDescriptor Describe() => CounterModuleDefinition.Describe();

    public void ConfigureServices(IServiceCollection services, ModuleContext context)
    {
        services.TryAddSingleton<ICounterLimitPolicy, DefaultCounterLimitPolicy>();
        services.TryAddSingleton<ICounterService, CounterService>();
        services.AddAggregateWireMapper<CounterState>(CounterAggregates.Counter, ToWire);
    }

    public void MapPlayerApi(IEndpointRouteBuilder routes)
    {
        routes.MapPlayerCommand<Wire.IncrementRequest, IncrementCommand, IncrementResult>(
            "/api/v1/counter/increment",
            IncrementHandler.Operation,
            ToDomain,
            result => new Wire.IncrementResult { Value = result.Value });
        // ... query /api/v1/counter/get (xem 4.9)
    }

    /// <summary>Wire → domain mapping and validation live in the adapter (ARC-02).</summary>
    private static IncrementCommand ToDomain(Wire.IncrementRequest request)
    {
        if (request.Note.Length > MaxNoteLength)
        {
            throw new GameServerException(CoreErrorCodes.BadRequest, $"note longer than {MaxNoteLength} characters.");
        }

        return new IncrementCommand(request.By, string.IsNullOrEmpty(request.Note) ? null : request.Note);
    }

    private static Wire.CounterState ToWire(CounterState state) => new() { Value = state.Value, Increments = state.Increments };
}

MapPlayerCommand<TWireRequest, TRequest, TResult>(route, operation, toDomain, toWire) (src/GameServer.Platform.Web/Commands/CommandEndpointFactory.cs):

  • route phải có đoạn version /v{n}/.
  • operation phải trùng tên trong CommandDescriptor.
  • toDomain: đọc param + validate dạng/độ dài (lỗi → BadRequest). Rule nghiệp vụ (số âm, vượt hạn mức) để trong handler (trả mã nghiệp vụ).
  • toWire: map result domain → message Protobuf.
  • Tự gắn profile Player, gate, timeout, rate limiter.
  • TryAddSingleton cho policy để game thay được bằng ReplacePolicy.

11. Quy tắc viết handler (tóm tắt) #

  1. Chỉ dùng ICommandContext và dependency đã tiêm; không HTTP, không DB, không file.
  2. Có thể bị gọi nhiều lần cho một request: không side effect ngoài ctx.
  3. Chỉ Set aggregate trong Touches; chỉ Get aggregate trong Touches/Reads.
  4. Giờ: ctx.Now. Random/ID: ctx.NewSeed/ctx.NewId.
  5. Lỗi nghiệp vụ: CommandOutcome.Reject(code) (không ném exception). Lỗi dạng/độ dài input: trong ToDomain.
  6. Hiệu ứng phụ: ctx.AddOutbox (+ OutboxProjection hoặc IOutboxConsumer); audit GM: ctx.AddAudit; analytics: ctx.AddAnalyticsEvent.
