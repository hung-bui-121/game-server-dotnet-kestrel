1. Tổng quan triển khai #

Một bản build (host, ví dụ SampleHost) chạy ở mọi môi trường. Môi trường được chọn bằng flavor = tên môi trường của host. Mỗi instance là một process ASP.NET Core/Kestrel stateless phía sau reverse proxy/load balancer. Toàn bộ trạng thái nằm trong Couchbase. Mỗi instance ghi file log và file analytics xuống đĩa của nó.

Mô tả dạng chữ của sơ đồ 1 (nodes và edges)
text
Nodes:
  [Client Unity]  [Trình duyệt GM]          (ngoài)
  [Reverse proxy / LB — TLS termination]    (biên)
  [Instance 1..N: host .NET 10 / Kestrel]   (cụm app; mỗi instance có 2 volume: logs/, analytics/)
  [Couchbase cluster ≥ 7.6]                 (bucket theo môi trường, scope g_<gameId>)
  [OTLP collector]                          (tuỳ chọn)
  [Log/analytics shipper]                   (sidecar hoặc agent node)
  [Dịch vụ ngoài: Google OAuth/Play API, static.gc.apple.com, IdP OIDC của công ty]
Edges:
  Client Unity  --HTTPS Protobuf-->  Proxy
  Trình duyệt GM --HTTPS JSON /gm/**--> Proxy
  Proxy --HTTP + X-Forwarded-For/-Proto--> Instance
  Instance --couchbases:// KV 11207 + HTTPS mgmt/query--> Couchbase
  Instance --OTLP grpc|http/protobuf--> Collector
  Instance --ghi file--> volume logs/, analytics/ --> Shipper --> data lake / log store
  Instance --HTTPS egress--> Dịch vụ ngoài
  Pipeline (một lần mỗi deploy) --"--provision" với identity quản trị--> Couchbase

2.2 Thư mục làm việc = content root (quan trọng) #

ASP.NET Core lấy thư mục hiện tại làm content root. appsettings*.json, config/ (GameServer:ConfigPath), logs (Observability:Logging:Directory) và analytics (GameServer:Analytics:Directory) đều tính từ đó.

ĐÃ CHẠY Chạy dotnet <đường dẫn>/SampleHost.dll --provision từ thư mục khác (C:\) với ASPNETCORE_ENVIRONMENT=Live cho exit 1:

text
 - [deployment] GameServer:DeploymentEnvironment is not set and the host environment name 'Live' is not a deployment
   environment (...). Fix: set GameServer:DeploymentEnvironment in appsettings.Live.json (found: no, content root C:\) ...

Vì vậy container/service phải đặt working directory = thư mục publish (Docker WORKDIR), hoặc truyền --contentRoot <dir>.

3.3 Fail-closed khi khởi động #

Mọi lỗi của một lần khởi động được in cùng lúc ra stderr, sau dòng Game server startup validation failed:. Mỗi lỗi một dòng - …, rồi host thoát với code 1 (HostExitCodes.InvalidConfiguration). Flavor sai hoặc thiếu không bao giờ thành Development.

ĐÃ CHẠY Artifact publish, ASPNETCORE_ENVIRONMENT=Live, không đặt biến nào, chạy server. Exit 1 với đúng 11 lỗi: DataProtection:MasterKey, Couchbase:ConnectionString, Couchbase:Username, Couchbase:Password, Identity:GuestPepper, năm khoá Iap:* và Gm:Oidc:Authority/ClientId/ClientSecret. Đây là cách nhanh để DevOps xem còn thiếu gì: chạy một lần với flavor đích rồi đọc danh sách lỗi. Không lỗi nào in giá trị.

5.3 TLS #

  • Live (Production) với couchbase:// thì exit 1. ĐÃ CHẠY: [couchbase] Couchbase:ConnectionString uses couchbase:// (no TLS) in 'Production'. Fix: use couchbases://, with Couchbase:TrustCertificatePath for a private CA …. Staging chỉ có warning, Development không có gì. Không có công tắc bỏ qua.
  • Couchbase:TrustCertificatePath là root duy nhất được tin cho cả KV lẫn HTTP. Trust store của OS không được dùng, tên host vẫn được kiểm (CouchbaseTrustedRoots.cs).
  • File phải là root CA tự ký. Trỏ vào intermediate thì chuỗi PartialChain và mọi kết nối bị từ chối.
  • DisableCertificateDownloads = true: host không tải certificate thiếu qua AIA, nên node Couchbase phải gửi kèm intermediate trong handshake.
  • Cổng phát hành TLS (bắt buộc trước mọi cutover Live; chưa từng chạy vì cluster local không có TLS) → 015. Hai test opt-in phải ra Passed, không phải Skipped (thiếu biến thì test tự skip qua Assert.SkipWhen):
    • CouchbaseSettingsIntegrationTests.Tls_trusts_the_configured_ca_and_refuses_another (class nằm trong tests/GameServer.Platform.Couchbase.IntegrationTests/CouchbaseSettingsTests.cs)
    • CouchbaseProvisioningTests.Production_provisions_without_runtime_secrets_and_serves_on_the_data_only_identity_over_tls (tests/GameServer.Platform.Couchbase.IntegrationTests/CouchbaseProvisioningTests.cs)

Biến: COUCHBASE_TLS_CONNSTR, COUCHBASE_CA_PATH, cùng các biến của fixture integration (COUCHBASE_CONNSTR, COUCHBASE_USERNAME, COUCHBASE_PASSWORD, COUCHBASE_BUCKET, xem README). Lệnh gợi ý (chưa chạy): dotnet test --project tests/GameServer.Platform.Couchbase.IntegrationTests -c Release --filter-method "*Tls_*" --filter-method "*_over_tls".

6. Mạng: reverse proxy, TLS, ForwardedHeaders #

  • TLS kết thúc ở LB/proxy (SEC-01). Kestrel nghe HTTP nội bộ và không được mở thẳng ra Internet. Code không có UseHttpsRedirection/HSTS, nên proxy chịu trách nhiệm redirect HTTPS.
  • GameServer:Hosting:ForwardedHeaders (ForwardedHeadersSettings): Enabled, KnownProxies[] (IP), KnownNetworks[] (CIDR), ForwardLimit (mặc định 1). Chỉ xử lý X-Forwarded-For và X-Forwarded-Proto, chỉ tin proxy trong danh sách. Bật mà danh sách rỗng, network /0, IP hoặc CIDR sai, hay ForwardLimit < 1 thì exit 1 (DeploymentChecks.cs).
  • Chuỗi CDN + LB: đặt ForwardLimit = số hop tin cậy. Để 1 thì IP client chính là IP edge của CDN, khiến rate limit theo IP (login) và audit sai.
  • SUY LUẬN X-Forwarded-Host không được xử lý, nên proxy phải giữ nguyên header Host. OIDC tạo redirect_uri từ scheme và host của request. Sau proxy TLS mà thiếu X-Forwarded-Proto tin cậy thì redirect URI thành http://… và IdP từ chối. Cookie GM vẫn Secure ngoài Development bất kể scheme (GmCookies.cs).
  • Route public (không cần xác thực): /health/live, /health/ready, /v1/time, cùng các route login và SSO. Khuyến nghị (không bắt buộc trong code): proxy chỉ cho /gm/** từ mạng nội bộ/VPN.
  • Egress cần mở: oauth2.googleapis.com, androidpublisher.googleapis.com (IAP Google), games.googleapis.com (Play Games), static.gc.apple.com (Game Center), authority của IdP OIDC, OTLP collector. Xác minh Apple JWS chạy offline (root CA lấy từ cấu hình).
  • AllowedHosts trong appsettings.json mẫu là *.

7.2 Graceful shutdown (OPS-03) #

text
SIGTERM → /health/ready = 503 ngay
        → vẫn nhận request thêm GameServer:Hosting:DrainDelaySeconds (5 s) để LB rút instance
        → ngừng nhận; request đang chạy có tới GameServer:Hosting:ShutdownTimeoutSeconds (25 s, tính cả drain)

  • Grace period của orchestrator ≥ 35 s (= ShutdownTimeoutSeconds + 10 s). Tăng ShutdownTimeoutSeconds thì tăng grace theo. ShutdownTimeoutSeconds phải lớn hơn DrainDelaySeconds, nếu không thì exit 1.
  • Đĩa analytics bị treo (I/O stall) không bị ngân sách drain giới hạn. Process đứng tới khi orchestrator kill. Payment vẫn an toàn (receipt chờ sweeper), login trong hàng đợi thì mất.
  • Đã drill trên Couchbase local (docs/guides/local-real-env-testing.md §5): dừng êm khi đang commit (ACC-28) và crash giữa commit.

8. Log và analytics trên đĩa #

8.1 Log (ObservabilityOptions.Logging) #

  • File {Logging:Directory}/{gameId}-{instanceId}-{yyyyMMdd}[_NNN].log, compact JSON (@t UTC).
  • Rolling 100 MiB mỗi file (FileSizeLimitBytes), giữ 30 file (RetainedFileCountLimit), RetainedFileTimeLimitDays tuỳ chọn. Theo mặc định là khoảng 3 GiB mỗi instance id SUY LUẬN.
  • Hàng đợi async 10 000 (BufferSize). Hàng đợi đầy thì bỏ dòng và đếm log_dropped_total, không chặn request.
  • Thư mục logs mặc định là tương đối, tức nằm trong filesystem của container. Đặt Observability__Logging__Directory vào volume bền, hoặc dùng sidecar shipper (LOG-03).
  • Che secret theo tên thuộc tính (token, password, secret, pepper, …). Exception và object log bằng {x} không được che.

8.2 Analytics (slice 012, AnalyticsOptions, section GameServer:Analytics) #

  • File {gameId}-{instanceId}-{event}-{yyyyMMdd}.jsonl (event login, payment), mỗi ngày UTC một file. File của ngày UTC trước là hoàn chỉnh.
  • Volume: volume local/block bền riêng cho mỗi pod. Không dùng NFS/SMB vì lock một-writer không đáng tin trên đó. Đặt đường dẫn tuyệt đối, ví dụ GameServer__Analytics__Directory=/var/lib/gameserver/analytics kèm volumeMounts.mountPath: /var/lib/gameserver/analytics. Thư mục mặc định analytics (tương đối) mất khi container bị thay.
  • Instance id: Observability:InstanceId → HOSTNAME → tên máy. Hai process dùng chung một thư mục mà trùng id thì process thứ hai exit 1. K8s Deployment đổi tên pod mỗi lần restart, sinh bộ file mới mỗi lần, và RetainLocalDays không dọn file của pod cũ. Dùng StatefulSet, hoặc đặt Observability:InstanceId cố định cho mỗi volume.
  • Múi giờ: GameServer:Analytics:TimeZone (tên IANA) bắt buộc ở Staging/Production. Flavor mẫu dùng Asia/Ho_Chi_Minh. Id Windows (SE Asia Standard Time) bị từ chối. Image phải có tzdata (mục 2.3).
  • GameServer:Analytics:Enabled phải giống nhau trên mọi instance của một deployment. Instance tắt sẽ ack entry payment của instance bật mà không ghi record.
  • Enabled=true mà host không đăng ký sink (không gọi AddAnalyticsFiles()) thì Staging/Production exit 1.
  • Độ bền: batch có payment được flush xuống đĩa (fsync) trước khi ack. Tốn khoảng +58 ms p95 cho một lần mua trên máy dev. Batch chỉ có login chỉ flush xuống OS.
  • Shipper (Vector, Fluent Bit, Filebeat): trễ ≤ 60 s (LOG-03). Coi file của ngày UTC trước là hoàn chỉnh. Tail file hôm nay được. Bỏ qua dòng không parse được (dòng bị cắt do crash có thể nằm giữa file).
  • Dung lượng khoảng 0,4 GB mỗi triệu login mỗi ngày (chưa nén). Payment không đáng kể.
  • Retention: server không xoá file, trừ khi đặt GameServer:Analytics:RetainLocalDays. Data lake giữ 25 tháng (chính sách của kho dữ liệu, server không cưỡng chế).
  • Key còn lại và mặc định: QueueCapacity 10 000, DeliveryTimeoutMs 500, ResumeTrackerCapacity 200 000, LowDiskBytes 1 GiB, ErrorWindowSeconds 300. Không key nào là secret.

8.3 Hazard rollback và dead letter của analytics #

  • Rolling deploy từ build trước 012: an toàn. Instance cũ gặp receipt có entry kind analytics thì ghi một attempt rồi backoff; instance mới giao.
  • Rollback toàn bộ về build trước 012: receipt còn chờ lúc đó bị build cũ thử lại, rồi dead-letter sau GameServer:Outbox:MaxRelayAttempts (10 lần, khoảng 3 h). Record payment thiếu cho tới khi re-drive.
  • Theo dõi outbox_dead_letter_total > 0. Re-drive tool (endpoint GM/ops) chưa có → 015. Re-drive thủ công trên Couchbase (đã chạy thử trong integration test):

10. Data Protection key ring (DataProtectionSettings, section DataProtection) #

  • Key ring dùng chung cho mọi instance của một deployment, lưu ở document dataprotection/keyring trong Couchbase. Không cần volume hay file share.
  • DataProtection:MasterKey: base64 của đúng 32 byte ngẫu nhiên, mã hoá key at rest (AES-256-GCM). Ngoài Dev/Test, thiếu hoặc sai thì exit 1.
  • Rotate master key: đặt MasterKeyId mới cùng MasterKey mới, chuyển khoá cũ vào DataProtection:PreviousMasterKeys:<id cũ> (secret, xem mục 4). Rotate key data-protection theo yêu cầu: POST /gm/v1/ops/dataprotection/rotate. Key kích hoạt sau RotationDelaySeconds (900).
  • Lịch: KeyLifetimeDays 90, ActivationLeadHours 48, RefreshMinutes 5.
  • Mất master key thì key ring không giải mã được: cookie GM, token CSRF và cookie OIDC đều hỏng SUY LUẬN. Dữ liệu player không bị ảnh hưởng. Sao lưu master key trong secret manager.
  • Data Protection dùng đồng hồ hệ thống, không dùng IClock.

13. Job, lease, xoá tài khoản #

  • Job trong ModuleDescriptor.Jobs chạy trên một instance tại một thời điểm, phối hợp bằng document leases/leases::{jobName} (CAS, không expiry). Bật/tắt bằng GameServer:Jobs:Enabled (mặc định true). Lease 60 s, renew 20 s, poll 30 s.
  • Không bao giờ xoá leases::* (PCR platform §16). Token tạo lại bắt đầu từ 1, trong khi purge record giữ token lớn hơn, nên các player đó bị bỏ qua mãi (LogError "never delete leases::*", account_purges_total{result=fenced_out}). Cách sửa: đặt fencingToken của leases::identity.account-purge (KV, CAS) lớn hơn token lớn nhất trong account_deletions.
  • Purge job identity.account-purge: mặc định 50 player mỗi 10 phút (khoảng 7 200/ngày) (GameServer:Purge:*). Grace trước purge là Identity:Deletion:GraceDays (30, 1..90).
  • Rủi ro vận hành mở (→ 015 runbook):
    • restore backup trước purge làm dữ liệu quay lại, nên phải chạy lại purge cho record purged;
    • tombstone Couchbase giữ key cũ khoảng 3 ngày;
    • retention log nên ≤ grace + thời gian purge, vì log giữ RequestId cạnh player id.

14. Đồng hồ (NTP) #

  • Node Couchbase: NTP bắt buộc (OPS-01, transaction).
  • Node app: server dùng đồng hồ hệ thống qua IClock. Thời gian ảnh hưởng tới:
